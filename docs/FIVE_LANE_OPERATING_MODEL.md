# 五线暴富机会作战模型

## 北极星

在不让单次失败毁掉本金的条件下，最大化捕捉加密市场极端右尾收益的概率。
系统不承诺收益；它交付的是比热榜更早、可执行、可复盘的机会事件。

每一条线都必须产出同一张事件卡：`Event → Thesis → Execution plan → Outcome`。
首次可观察价格、发现延迟、流动性、失效价和最大可成交仓位一经记录不可改写；之后的扫描只能补充状态和结果。

## 路线与代码边界

| 线 | 收益结构 | 当前入口 | 下一步缺口 | 不该做的事 |
|---|---|---|---|---|
| Launch | 低流通早期定价重估，右尾主引擎 | `launch_radar.py`、`launch_execution.py`、GMGN | Solana/Base 流式首池与首批钱包、从只读双向报价升级为真实成交回放 | 用热度/单一分数代替时延和可卖性 |
| Cascade | 杠杆拥挤开始平仓时的流动性真空 | `hyperliquid.py`、`liquidation_monitor.py` | WebSocket、OI/盘口/清算事件状态机、双向结果账本 | 仅因高资金费裸做反向 |
| Structure | 公开催化剂、上币、解锁、CEX 流、跨所结构价差 | `listing_detector.py`、`cex_flow.py`、`token_unlocks.py`、`carry_paper.py` | 统一日历与可交易窗口、来源可信度 | 漏洞、未公开信息抢跑、攻击或恶意 MEV |
| Airdrop | 低下行的长期期权/劳务回报 | `airdrop_radar.py`、官方活动清单 | 项目资格、成本、快照证据、领取/卖出追踪 | 多号 Sybil 或违反项目条款的自动化 |
| Convexity | 高杠杆单边行情的严格限额彩票仓 | `perp_scanner.py`、`execution_advisor.py` | 与主账户隔离的风险预算、失效和爆仓模拟 | 把幸存者收益当可重复 alpha |

## 第一阶段：Launch Radar

`src/pipeline/launch_radar.py` 每 3 分钟读取公开 DEX 首发资料与池数据，筛出：

- 支持链上的可交易池；
- 池龄不超过 24 小时，FDV $10k–$10m，流动性 $5k–$2m；
- `SMALL_PROBE` 还需池龄 <3 小时、5 分钟买方占优且成交额达到流动性的 1.5%；
- 最大名义仓位为流动性的 0.3%，且限制在 $25–$500；失效价暂定为首次价的 -30%。

这些是执行和存活门槛，不是预测模型。结果以 `opportunity_ledger.py` 的首次观察快照记录，并在网站的 `🚀 Launch` 作战台展示。

原始候选还不能直接成为 `SMALL_PROBE`。`launch_execution.py` 先做 GoPlus
安全检查，再用拟议仓位进行买入→卖出双向路由报价：Solana 使用 Jupiter
Swap V2 `/order` 且不传 `taker`（只返回报价、不构建交易），
EVM 记录 0x 指示价但在 gas 未折算为美元前仍只允许 WATCH。缺 key、缺字段、
取数失败均为 UNKNOWN；蜜罐、可冻结/改余额/高卖税或无卖出路由为 AVOID。
报价是只读快照，不是实盘成交；配置项为 `JUPITER_API_KEY`、`ZEROX_API_KEY`。
修复前的旧账本允许决策随轮询刷新，因此这些事件只保留在总体结果分布中，
不会进入 `SMALL_PROBE` 对 `WATCH` 的 cohort 比较；只有 `cohort_version=2`
且首次决策已冻结的新事件可以用于相对 edge 判断。

## 统一验收指标

1. **P95 发现延迟**：链上/池创建到事件入账的秒数；不能以看板刷新时间代替。
2. **可执行率**：按当时深度和滑点实际能以计划大小成交的事件比例。
3. **独立事件数**：同一币的一连串轮询只算一个 Launch；Cascade 按一次启动—结束算一个 episode。
4. **净结果分布**：1h、24h、7d、峰值、最大回撤、含费用/滑点的净额；展示中位数和 P90/P99，而不是只列赢家。
5. **生存约束**：每线都有最大损失/最大并发/停机条件；右尾策略最先优化的是活到下一次机会。

`opportunity_outcomes.py` 按账本中不可改写的首次发现价结算 1h、24h、7d。
Launch/Cascade 会扣除事件发现时冻结的往返成本估算，但该估算不是实盘成交证明；
只有样本达到 20 才展示分布。Launch 的 `SMALL_PROBE` 必须与同一候选宇宙的
`WATCH` 同期对照，置信区间未分离时仍显示“不可判”。没有方向假设的 Structure
事件不计算命中率，Carry 与 Airdrop 分别使用资金费净额和领取净回报账本。

## 空投的证据门

`config/airdrop_watchlist.yaml` 是人工维护、明确不完整的官方活动登记，不是全市场空投发现器。每一项的活动页和不同的证据/条款页都必须位于 `airdrop_radar.py` 中经过代码审计的 HTTPS 信任根下，并在每轮扫描实际读取页面、匹配全部标志文本；重定向离开信任根、网络失败或内容变化都会降为 `source_unverified` 和 `WATCH`。当前登记从 Starknet 官方页面开始，不能外推为其他生态覆盖。

来源通过只证明页面归属，不证明钱包资格、回报或活动仍有额度。只有自己控制的钱包和任务证据齐全后才会显示为“已记录”；未知成本不能写成 0，占用资本、KYC 和活动风险必须单列。系统不会读取私钥、不会猜测资格、不会做 Sybil、多号或自动交互。

## 已停用的错误路径

旧的 `config/token_unlocks.yaml` 已过期，而免费解锁源曾出现资产错配/伪造排期。因此 `signal_generator.check_token_unlocks()` 只能作为结构事件的未来数据入口，当前被硬门禁为不生成自动做空信号；只有接入带资产级来源证明的数据并完成独立事件回放后才可恢复。

## 产品原则

- 网站的顶层导航按五条赚钱结构组织，不按数据源组织。
- `WATCH` 是合格的答案；没有可执行机会时明确显示空白。
- 所有“可试错”都必须包含价格、失效、大小和来源；没有这四项不能显示为操作。
- 证伪不是限制增长，而是禁止事后改价、重复计数和把无法成交的纸面收益当收益。
